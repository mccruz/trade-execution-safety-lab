# Recruiter discoverability and SEO checklist

## Implemented locally

- Descriptive stable repository name with the domain and engineering objective.
- One README H1 and a plain-language opening that names Python, broker/exchange
  automation, execution safety, and the offline boundary.
- Crawlable text for architecture, controls, evidence, limitations, provenance,
  and setup; no important claim exists only in an image.
- Descriptive image alt text and link labels.
- Three-minute no-install recruiter path before technical setup.
- Beginner-safe virtual-environment instructions for Homebrew Python.
- Focused, truthful proposed GitHub description and topics.
- Accessible architecture SVG and 1280 by 640 social-preview source.
- No keyword stuffing, profitability language, or unsupported integration claim.

## Publication checks

- Upload and re-download the social preview; compare it with the approved PNG.
- Confirm repository description, topics, MIT license detection, and default
  branch while signed out.
- Confirm README images and links return successfully from the public repository.
- Confirm GitHub Actions badges or status links only after the first successful
  run.
- Add the project to the profile README only after publication verification.
- Defer final pinned-repository order until the complete portfolio plan is done.
